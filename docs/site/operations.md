# 管理画面・配送の確認

## 毎日の確認

**Overview** で失敗・再試行中のメールと、期限が近い credential を確認します。対象を開くと **Messages** やリソース詳細に進めます。検索条件・ページ番号は URL に残るため、確認中の画面をブックマークできます。

## 2 つの診断を使い分ける

Mailboxes の詳細にある **Diagnostics** を使います。

| 操作 | 確認できること | 確認できないこと |
| --- | --- | --- |
| Check authentication | OAuth トークンを取得できるか | メールボックスの送信権限、機器のログイン、実際の配送 |
| Send test email | 指定した 1 宛先へ通常のキューを通して送信できるか | 機器の SMTP 設定、受信箱への最終到達 |

テストメールは実際に送信されます。自分が管理する宛先を入力して実行し、表示されたメッセージの状態を確認してください。診断送信は `diagnostic`、機器からの送信は `smtp` として区別されます。

## Messages の状態と操作

| 状態 | 意味・次の確認 |
| --- | --- |
| `queued` | 配送待ち。ワーカーの処理を待つ |
| `sending` | 配送中。完了するまで操作を待つ |
| `deferred` | 一時エラーなどで再試行待ち。最後のエラーを確認 |
| `sent` | Microsoft 365 が受け付けた。受信側は別途確認 |
| `failed` | 配送失敗。原因を直した後に Retry |
| `held` | 保留中。再開する場合は Retry |

**Retry** は `failed` / `deferred` / `held`、**Hold** は `queued` / `deferred` / `failed` に使えます。`sending` のメッセージは再試行・保留・削除できません。`sent` の削除は履歴と本文を消す操作で、送信済みメールの取り消しではありません。

既定の再試行設定は最大 12 回・最大経過時間 72 時間で、バックオフは `1m, 5m, 15m, 1h, 4h, 12h`（jitter あり）です。設定で変更できます。

## 利用者の権限

| ロール | 主な操作 |
| --- | --- |
| viewer | 状態・設定の参照 |
| operator | 上記に加えて診断、キュー操作、監査ログの参照 |
| admin | 上記に加えて設定・アカウント・利用者の管理、メッセージ本文の取得 |

SMTP accounts は機器用、Users は管理画面用です。機器廃止時は該当 SMTP アカウントを無効化し、他の機器に同じパスワードを使い回さない運用にします。

## シークレットの更新

Entra で新しいシークレットを作成し、Credentials のシークレット置き換え操作で更新します。共有しているメールボックスを確認し、認証確認とテスト送信が成功してから旧シークレットを廃止します。通常の属性編集と、シークレット・SMTP パスワードの置き換えは別操作です。

`bootstrap` 管理の項目は UI では編集できないことがあります。[設定ファイルの管理方式](./configuration.md#bootstrap)を確認してください。
